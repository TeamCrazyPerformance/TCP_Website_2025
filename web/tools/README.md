# 프런트엔드 개발 도구

`web/tools`는 백엔드나 데이터베이스 없이 프런트엔드 화면을 확인하기 위한 개발 도구 모음입니다.
Mock API 서버와 개발 서버를 실행해 데모 데이터로 화면을 확인할 수 있습니다.

## 실행 범위

이 디렉터리의 스크립트는 프런트엔드 빌드 번들과 최종 컨테이너 이미지에 포함되지 않습니다.

- `CICDtools/PrivateQuickDeploy/Dockerfile.web`은 최종 이미지에 빌드 결과물인 `/app/dist`만 복사합니다.
- 프런트엔드 애플리케이션은 이 디렉터리의 스크립트를 런타임에 불러오지 않습니다.
- 도구는 직접 실행할 때만 동작하며, 저장소를 내려받는 것만으로 실행되지 않습니다.

### 데모 데이터와 개인정보

빌드 번들에서 제외되는 것과 저장소에서 공개되지 않는 것은 다릅니다.
공개 저장소에 포함된 개발 도구와 데이터는 누구나 열람하거나 내려받을 수 있습니다.

- 회원·공지·스터디·팀 데이터는 `shared-demo-data.mjs`에서 합성 데이터로 생성합니다.
- 이름은 `데모 회원 01`처럼 가상임을 알 수 있는 형식을 사용합니다. 자기소개·소속·모임 안내도 실제 정보를 복사하지 않습니다.
- 연락처·포트폴리오·초대 링크에는 실제 수신자나 서비스로 연결되지 않는 예약 도메인 `example.invalid`를 사용합니다.
- 개인 계정명과 개인 식별자가 들어간 이미지 경로는 사용하지 않습니다. 프로필과 활동 이미지는 로컬 기본 이미지로 대체합니다.
- 개발 환경의 대체 회원·팀 목록도 합성 이름과 예약 도메인을 사용합니다.
- 공개 테크 아티클의 출처·뉴스 예제와 회원 프로필은 구분합니다. 사이트에 공개된 회원 정보나 게시물이라도 Mock 데이터에 그대로 복제하지 않습니다.
- 실제 데이터가 들어 있는 내보내기 파일, 금지어 목록, 테스트 예상값을 저장소에 추가하지 않습니다. 현재 파일을 교체해도 과거 Git 기록은 제거되지 않습니다.

합성 데이터 규칙과 Mock API 응답은 저장소 루트에서 다음 명령어로 검증합니다.

```bash
node --test web/tools/shared-demo-data.test.mjs
```

## 개발 서버 실행

`dev.sh`는 Mock API 서버와 Create React App(CRA) 개발 서버를 함께 실행합니다.
Node.js 18.11 이상과 `web/`의 의존성 설치가 필요합니다.

저장소 루트에서 다음 명령어를 실행합니다.

```bash
bash web/tools/dev.sh
```

실행 후 [스터디 목록](http://localhost:3100/study)에 접속해 화면을 확인합니다.
`web/` 디렉터리에서 실행할 때는 `bash tools/dev.sh`를 사용합니다.

- Mock API 서버의 기본 포트는 `3000`이며, `web/package.json`의 `proxy` 설정과 일치해야 합니다.
- 프런트엔드 개발 서버의 기본 포트는 `3100`입니다.
- `Ctrl+C`를 누르면 두 서버가 함께 종료됩니다.
- Mock API 서버는 `tools/`의 파일이 변경되면 자동으로 재시작합니다. 변경된 데이터는 브라우저를 새로고침해 확인합니다.
- 프런트엔드 소스 변경은 CRA의 자동 갱신 기능으로 반영됩니다.

주의: 이 환경에서는 실제 API 대신 데모 데이터를 사용합니다. 실제 API와의 연동을 확인할 때는
이 스크립트를 사용하지 않습니다. 지정한 포트가 이미 사용 중이면 스크립트가 종료되며,
기존 서버를 대체하거나 종료하지 않습니다.
개발 환경에 `REACT_APP_API_BASE`를 지정한 경우에는 해당 주소를 우선 사용하므로,
Mock API 서버를 가리키는지 확인합니다.

## Mock API 서버 단독 실행

`mock-tech-articles-api.mjs`는 화면 확인에 필요한 API 응답을 제공합니다.
Node.js 18 이상에서 별도 패키지 설치 없이 실행할 수 있습니다.

저장소 루트에서 다음 명령어를 실행합니다. 이 예시에서는 기본 포트 `3000` 대신 `4000`을 사용합니다.

```bash
PORT=4000 node web/tools/mock-tech-articles-api.mjs
```

`web/` 디렉터리에서 실행할 때는 `PORT=4000 node tools/mock-tech-articles-api.mjs`를 사용합니다.
포트를 변경해도 CRA의 `proxy` 설정은 자동으로 변경되지 않습니다.
단독 실행한 서버는 파일 변경 후 직접 재시작해야 합니다.

### 지원 화면

- 홈·공지·스터디·멤버·팀·모집 공개 화면에 필요한 응답을 제공합니다.
- 테크 아티클 공개 화면과 관리자 목록·검수 큐·크롤링 관리 화면에 필요한 응답을 제공합니다.
- 크롤링 실행 이력에는 대기·실행·재시도·완료·일부 성공·실패 사례를 제공합니다.

크롤링 실행 중에는 숫자 진행률을 제공하지 않으며, 실제 어댑터 계약과 동일하게
여섯 가지 수집 통계는 완료·일부 성공·실패로 종료된 실행에만 제공합니다.
로컬 로그인 화면에서 비어 있지 않은 아이디와 비밀번호를 입력하면 데모 관리자로 로그인할 수 있습니다.

### 접근 범위와 제한 사항

Mock API 서버는 기본적으로 로컬 루프백 주소인 `localhost`에서만 요청을 받습니다.
격리된 개발망에서 다른 기기의 접근이 필요한 경우에만 `MOCK_HOST=0.0.0.0`을 지정합니다.
외부 접근을 허용하면 데모 관리자 인증도 노출되므로 인터넷이나 공용 네트워크에는 공개하지 않습니다.

데이터는 메모리에 저장되며 서버를 재시작하면 초기화됩니다.
실제 서버와 동일한 입력 검증·권한 검사·동시성 제어는 구현하지 않으므로 화면 확인 용도로만 사용합니다.

### 테크 아티클 데이터

기본 데이터는 공개 아티클 106건과 관리자 검수용 비공개 아티클 24건으로 구성됩니다.
공개 목록의 첫 페이지 20건은 운영 화면의 제목·한 줄 요약·출처·태그 조합을 기준으로 구성합니다.
공개 아티클 중 9건의 수집 시각은 서버 실행 시점을 기준으로 최근 시각으로 설정합니다.
새 글 표시는 수집 시각뿐 아니라 원문 게시 시각도 기준을 충족해야 합니다.

데이터 규모는 `MOCK_ARTICLE_COUNT`와 `MOCK_PUBLIC_ARTICLE_COUNT` 환경 변수로 조정할 수 있습니다.

공개 목록과 상세 응답은 운영 API와 동일한 허용 목록을 사용합니다.
목록의 `source`에는 `name`과 `domain`만 포함하고, 상세에는 `path`와 `articleUrl`을 추가합니다.
소스 ID·수집 방식·작성자와 내부 평가 버전·판정·근거·신호는 공개 응답에 포함하지 않습니다.
공개 상세의 `valueScore`는 회원 요청에만 포함합니다.

로컬 데모 로그인 후 다음 상세 페이지에서 스터디장과 일반 회원의 표시를 확인할 수 있습니다.

| 상세 경로   | 스터디                       | 참여 인원 |

### 스터디 목록 상태 구분

`/study`에서 예정·진행 중, 종료, 기간 미확인 스터디의 분류를 확인할 수 있습니다.
모든 스터디에는 `[데모]` 표시가 있습니다. 월 단위 기간 예제 5건과 진행 중·진행 예정·기간 미정 사례를 제공합니다.
진행 중·진행 예정 사례의 날짜는 서버 실행일을 기준으로 생성합니다.
목록의 `status`는 실제 API와 동일하게 진행 기간과 한국 시간을 기준으로 계산합니다.

## API 계약 동기화

Mock API 서버는 실제 API와 파이프라인의 규칙을 재현합니다.
서버의 응답 구조나 처리 규칙을 변경할 때는 다음 항목도 함께 수정합니다.

| Mock API 서버 항목                         | 대응하는 서버 규칙                                                 |
| ------------------------------------------ | ------------------------------------------------------------------ |
| `REACHABLE_STATES`                         | `persistence/mysql.py`의 상태 전이와 도달 가능한 3축 조합          |
| `articleStage()`                           | `persistence/mysql.py`의 `STAGE_PREDICATES`                        |
| `hasStatusMismatch()`                      | `persistence/mysql.py`의 `STATUS_MISMATCH_PREDICATE`               |
| `publicationQueue()`                       | `persistence/mysql.py`의 `_review_conditions("publication")`       |
| `applyPublication()`                       | `persistence/mysql.py`의 `apply_publication_action`                |
| `demoCrawlRuns`                            | 크롤링 실행·작업 상태와 종료 시점의 `CrawlRunCompleted.statistics` |
| `evaluationOf()`                           | 관리자 화면용 `score.axes`와 레거시 점수 호환 구조                 |
| `publicValueScoreOf()`                     | 공개 화면용 `overall`, `scale`, 표시명·기여도로 구성한 `breakdown` |
| 공개 상세의 인증 헤더 분기                 | NestJS Optional JWT 응답과 회원 요청의 `valueScore` 포함 여부      |
| 아티클당 태그 개수                         | 요약기의 `maximumTagCount`와 `contracts/models.py`의 기본값 3      |
| `TAGS`                                     | 요약기의 `ALLOWED_TAGS` 15개                                       |
| `study-period.mjs`의 `studyPeriodStatus()` | `api/src/study/study-period.ts`의 기간 해석 규칙                   |

표의 `persistence/mysql.py`와 `contracts/models.py`는
`tech-article-pipeline/core/src/tech_article_pipeline/`을 기준으로 한 경로입니다.

주의: `applyPublication()`의 `reviewStatus = "APPROVED"` 처리는 알려진 서버 결함을 재현합니다.
서버에서 이 처리에 단계 조건을 추가하거나 동작을 변경하면 Mock API 서버의 해당 코드도 함께 수정합니다.
